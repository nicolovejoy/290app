# Week-one build plan

Spec: `init.md` (binding). This plan implements spec §5 steps 1–5.

## Global Constraints

- Layout in this one local repo mirrors the GitLab projects: `template/` = `staff/template`, `tooling/` = `staff/tooling`, `dashboard/` = `staff/dashboard`. The results store (`staff/results`) is a separate GitLab project written via API; it has no folder here.
- Python >= 3.12, managed with `uv`. A single root `pyproject.toml` (no package build; `[tool.uv] package = false`). Runtime deps: `python-gitlab`, `anthropic`, `pyyaml`. Dev dep: `pytest`. Root pytest runs only `tooling/tests` (`testpaths = ["tooling/tests"]`); assignment tests under `template/assignments/*/tests` are student tests run by CI, not by the root suite.
- Dashboard is plain browser JS, no build step, no npm dependencies. Its pure logic is tested with `node --test` (Node 20).
- Tests never touch the network: GitLab and Anthropic clients are faked/mocked.
- Secrets only from env vars: `GITLAB_TOKEN` (provisioning, staff), `REVIEW_BOT_TOKEN` (CI bot, group-level variable), `ANTHROPIC_API_KEY`. `GITLAB_URL` env var, default `https://gitlab.oit.duke.edu`.
- Group path is `duke-cs-claude-<term>`, passed as `--group` / `COURSE_GROUP` env.
- This code is built live in front of a class: small, readable files, short functions, light comments explaining *why*. No speculative abstraction. Each task ends with one or more commits on branch `week1-build`.
- Rulings already made (from spec §7 proposals): flag when `needs_human` OR `recommended_score < 0.6` OR `abs(test_score - correctness_score) > 0.2` where `test_score = passed/total` and `correctness_score = rubric_scores["correctness"].score / .max`. Results file path is `<assignment>/<netid>.json` in the results project, containing a JSON array of run records (spec §4.3). Reviewer sees only the one MR. Session logs are opt-in (process score 0 if absent).

## Task 1: Project scaffold + provision.py (spec §3.3)

Files: `pyproject.toml`, `tooling/provision.py`, `tooling/tests/test_provision.py`, `tooling/tests/conftest.py` (if needed).

- `uv init`-style root `pyproject.toml` per Global Constraints; run `uv sync` so `uv run pytest` works.
- `provision.py --csv roster.csv --group duke-cs-claude-fa26 [--dry-run]`. CSV columns `netid,name,email` with header row.
- For each row, idempotently:
  1. Find project `<group>/students/<netid>`. If absent, fork `<group>/staff/template` into namespace `<group>/students` with `path=netid`, `name=netid`.
  2. Look up GitLab user by `username=netid`. If not found, print a warning line and continue to the next student (don't crash; the student may not have logged in to GitLab yet — re-running later fixes it).
  3. Ensure the user is a member with Developer access (30) on that project. Existing member with different level → update to 30.
  4. Ensure `main` is protected with push_access_level=0 (no one) and merge_access_level=30. If already protected with those levels, do nothing.
- `--dry-run` prints the actions it would take and calls no mutating API.
- Print one line per student summarizing what changed (`created`, `added member`, `protected main`, or `ok`).
- Use `python-gitlab`; paginate with `get_all=True` / `iterator=True` where listing.
- Structure: `main()` parses args and builds the client; `provision_student(gl, group, row, dry_run)` does the per-row work and returns the list of actions — that is the unit under test.
- Tests with a fake/mocked `gitlab.Gitlab`: new student (all actions), already-provisioned student (no mutating calls, `ok`), user not found (warning, no member call, fork still happens), dry run (no mutating calls), existing member at wrong level gets updated.
- Target ~100 lines for `provision.py`.

## Task 2: CI pipeline, detect + test stages (spec §3.4 stages 1–2, §3.2)

Files: `tooling/ci/review-pipeline.yml`, `template/.gitlab-ci.yml`, `tooling/review/detect.py`, `tooling/tests/test_detect.py`, `template/assignments/01-warmup/` (README.md with fenced `rubric` block in spec §4.1 format, a small Python starter `solution.py`, `tests/test_solution.py`), `template/CONTRIBUTING.md`.

- `template/.gitlab-ci.yml` contains only an `include:` of `project: duke-cs-claude-$TERM/staff/tooling`, `file: ci/review-pipeline.yml` (use a `ref: main`). Note: GitLab `include:project` can't interpolate arbitrary vars in all versions — use a literal placeholder `duke-cs-claude-TERM` with a comment telling the instructor to set it once per term.
- `review-pipeline.yml` stages `detect`, `test`, `review`. Only runs on `merge_request_event` pipelines. The `review` stage job is defined here but its script just calls `python tooling/review/review.py` (implemented in Task 3); the tooling repo is fetched in the job via `git clone` of `staff/tooling` using `REVIEW_BOT_TOKEN`.
- `detect.py`: pure function `detect_assignments(changed_paths) -> list[str]` returning sorted unique `assignments/<nn>-<slug>` dirs matching `^assignments/\d{2}-[a-z0-9-]+/`. CLI: reads changed files from `git diff --name-only $CI_MERGE_REQUEST_DIFF_BASE_SHA...HEAD`, writes the result to `detect.env` as `ASSIGNMENT=<dir>` (dotenv artifact for later jobs).
  - Zero assignments: post MR note "No assignment detected in this merge request — changes must be inside an `assignments/<nn>-<slug>/` folder." via python-gitlab with `REVIEW_BOT_TOKEN`, then exit 0 with `ASSIGNMENT=` empty; later jobs skip when empty.
  - More than one: post note asking the student to split into one MR per assignment; same skip behaviour. (Ruling: v1 reviews one assignment per MR.)
- `test` job: if the assignment dir has `package.json`, run `npx jest --ci --reporters=default --reporters=jest-junit`; else `pytest <dir>/tests --junitxml=junit.xml`. Publish `junit.xml` as `artifacts:reports:junit` and as a plain artifact for the review job. Test failures must not fail the pipeline before review runs (`allow_failure: true` or `|| true` with the XML kept) — the score comes from the XML.
- Tests: `detect_assignments` cases (none, one, two, nested files, non-matching like `assignments/README.md` or `assignments/x/`); note-posting path with a mocked gitlab client.

## Task 3: review.py with Claude call + flag (spec §3.4 stages 3–4, §4.2, §4.3)

Files: `tooling/review/review.py`, `tooling/review/prompt.md`, `tooling/review/schema.py` (or inline), `tooling/review/flag.py`, `tooling/tests/test_review.py`, `tooling/tests/test_flag.py`, `tooling/tests/fixtures/` as needed.

- Before writing the Claude call, load the `claude-api` skill and use the current SDK idiom for structured outputs (JSON schema) and prompt caching. Model: `claude-sonnet-5-5` via a `REVIEW_MODEL` constant (env override `REVIEW_MODEL`).
- Inputs: MR diff restricted to the assignment folder (`git diff $CI_MERGE_REQUEST_DIFF_BASE_SHA...HEAD -- <assignment>`), the assignment README's fenced `rubric` YAML block, `junit.xml` (parse passed/total), and `.claude-sessions/*.jsonl` files changed in the MR if present.
- Diff truncated beyond `MAX_DIFF_BYTES = 60_000` with an explicit truncation note in the prompt and in the posted comment. Session log text capped at 20_000 bytes similarly. `max_tokens` capped (4096).
- System prompt in `prompt.md` (fixed, cached). Rubric + instructions also in a cached block; diff/tests/session log in the uncached user turn.
- Output schema exactly spec §4.2. Validate the parsed result has the required keys; on API/parse failure post a short "automated review failed, a TA will look" note, add `needs-review`, exit non-zero.
- Debounce: before calling Claude, find the bot's existing review note (identified by a hidden marker `<!-- claude-review -->` at the top). If its `updated_at` is < 10 minutes ago, print a skip message and exit 0. (Ruling: debounce in review.py, since GitLab `rules:` can't compare timestamps.)
- Post/edit one MR note: summary, 3–6 comments as `file:line — severity — text`, rubric score table, recommended score, next steps. Header states the score is a recommendation, not a grade. Edit the marked note if it exists, else create it.
- Results: append a record `{...review_output, mr_iid, commit_sha, timestamp, test_passed, test_total}` to `<assignment>/<netid>.json` in project `RESULTS_PROJECT` (default `$COURSE_GROUP/staff/results`) via the repository files API (create if missing, else update), commit message `review: <netid> <assignment> !<mr_iid>`. `netid` = student project path (`CI_PROJECT_NAME`).
- `flag.py`: pure `should_flag(review, test_passed, test_total) -> (bool, reason)` implementing the Global Constraints rule. `test_total == 0` → treat test_score as unknown: skip the disagreement check. Missing `correctness` rubric key → skip disagreement check. When flagged, add MR label `needs-review` (don't remove it on later clean runs — removing is a human decision).
- Structure review.py so pure pieces are testable without network: `build_prompt(...)`, `truncate(...)`, `parse_junit(...)`, `render_note(...)`, `extract_rubric(readme_text)`. `main()` wires env + clients.
- Tests: truncation, junit parsing, rubric extraction, note rendering (marker present, recommendation wording), debounce skip, note create vs edit, results append (new file vs existing array), Claude call with mocked client returning schema-valid output, failure path, all `should_flag` branches including the boundaries (0.6 exactly is not flagged; 0.2 disagreement exactly is not flagged).

## Task 4: Dashboard v1 (spec §3.7)

Files: `dashboard/index.html`, `dashboard/app.js`, `dashboard/app.test.mjs` (or `.js` per module choice), `tooling/ci/` not touched. Optional `dashboard/.gitlab-ci.yml` deploying to Pages (copy files to `public/`).

- No backend, no build. `index.html` + `app.js` (ES module). On first load, prompt for GitLab URL, results project path, and a read-only token via a small form; store in `localStorage` (never in source). "Sign out" clears it.
- Fetch: list repository tree of the results project recursively (paginate), then fetch each `*.json` raw file. Use `PRIVATE-TOKEN` header.
- Views via hash routing:
  - `#/` grid: rows = students (netid), columns = assignments; each cell shows latest run's test score (passed/total), recommended score, and a flag marker; empty cell = not submitted.
  - `#/flagged`: runs whose latest record is flagged per the same rule as `flag.py` (port the function to JS; keep thresholds as named constants matching Task 3), sorted by urgency: `integrity_flag` first, then `needs_human`, then lowest recommended_score. Each row links to the MR (`<gitlab>/<group>/students/<netid>/-/merge_requests/<mr_iid>`).
  - `#/student/<netid>`: all submissions with per-run history (trend = list of recommended scores over time).
- Pure logic (`latestRun`, `isFlagged`, `urgencySort`, `buildGrid`) exported from `app.js` and tested with `node --test` against fixture records. DOM code stays thin.
- Plain readable CSS in `index.html`; works at phone width.

## Task 5: Session-logging hook (spec §3.6)

Files: `template/.claude/settings.json`, `template/.claude/hooks/log_session.py`, `tooling/tests/test_log_session.py`, `template/.gitignore` if needed (must NOT ignore `.claude-sessions/`).

- `settings.json` registers the hook on `UserPromptSubmit` and `Stop`, command `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/log_session.py"`. Check current Claude Code hook settings format/stdin payload fields via the `claude-code-guide` knowledge or docs before writing (do not guess field names).
- The script reads the hook JSON from stdin and appends one JSON line to `$CLAUDE_PROJECT_DIR/.claude-sessions/<YYYY-MM-DD>.jsonl`: `{"ts": ISO8601, "session_id", "event": "prompt"|"response", "text": <truncated to 2000 chars>}`. For `UserPromptSubmit`, text = the prompt. For `Stop`, text = the last assistant message text from the transcript file at `transcript_path` (JSONL), truncated.
- Must never block or fail the student's session: any exception → write nothing, exit 0. Never print to stdout (UserPromptSubmit stdout is injected into context).
- Standard library only.
- Tests run the script as a subprocess with crafted stdin and a temp project dir: prompt event, stop event with a fixture transcript, malformed stdin (exit 0, no file), append-only (two events → two lines).
- Update `template/CONTRIBUTING.md` (from Task 2) with a short note on committing `.claude-sessions/`.
